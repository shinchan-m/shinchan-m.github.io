把 DeepSeek 接进 QQ 小号的一次完整实战

📅 2026-10-28  |  AstrBot NapCat DeepSeek QQ机器人 踩坑记录

记录 AstrBot、NapCat、DeepSeek 和插件配置的完整过程，也写下插件卡死、ffmpeg 缺失、账号登录反了这些真实坑。

我想做一个不太像客服的 QQ 机器人。它用 DeepSeek 生成回复，用一套配置包记住自己的性格，能在私聊里正常接话，也能在群里偶尔插一句。搭完以后，我发现真正耗时间的部分并不在安装，而在几个看起来像“卡死”的小问题。

这篇文章按我实际走过的顺序写。版本以搭建当天为准，AstrBot Launcher 是 0.3.13，AstrBot 是 4.29.3，NapCat 是 4.18.41，对话模型用 deepseek-flash。软件更新以后按钮位置可能变化，思路和排查顺序仍然能用。

先提醒一句。用 NapCat 这类第三方方式登录 QQ，可能触发腾讯的风控，也可能违反 QQ 使用协议。本文只记录正常配置过程，不提供绕过验证或规避风控的方法。准备尝试就用自己的小号，别拿常用大号冒险。

这套东西各自负责什么

组件 作用
AstrBot 机器人大脑，负责后台、人格、模型和插件
NapCat 登录 QQ 小号，把 QQ 消息转给 AstrBot
DeepSeek 真正生成回复的模型，通过 API 调用
配置包 一次性写入人格、插件参数、记忆和语音设置
LivingMemory 长期记忆，把以前聊过的内容总结后重新检索

QQ 小号负责在线，NapCat 负责收发消息，AstrBot 负责决定怎么回复。DeepSeek 在云端工作，本地不需要下载几 GB 的模型。把这些角色分清以后，日志里谁出了问题会容易判断很多。

安装 AstrBot

我用了 AstrBot 的图形启动器。安装路径放在 D:\Astrabot，实例版本选择 4.29.3。组件管理里先下载好 Python、uv 和 Node.js，再创建实例。第一次部署会创建虚拟环境、安装依赖、检查 WebUI，整个过程比普通桌面软件慢，但启动器会显示阶段。

实例运行起来以后，浏览器打开启动器给出的地址，登录后台并修改默认密码。后台地址通常只监听本机，随机端口每次可能变化，以后不要照抄文章里的端口号，以启动器当前显示的为准。

后台里有四项安全设置需要先处理。

  1. 给访问控制开启白名单，只允许自己的会话。
  2. 把自己的 QQ 号加入管理员列表。
  3. 确认“使用电脑能力”的运行环境是“不允许任何环境”。
  4. 把 DeepSeek Key、OneBot Token、后台密码和 NapCat WebUI Token 当成密码保管，不截图，不发群。

白名单会话 ID 可以先用大号给小号发送 /sid 取得。格式通常包含机器人名称、消息类型和自己的 QQ 号，机器人名称必须和后台创建时一致。

接上 NapCat 和 QQ

NapCat 的一键包装好以后，目录里会出现一个 NapCat.<数字>.Shell 文件夹。日常启动只需要运行里面的 NapCatWinBootMain.exe。NapCatInstaller.exe 只负责安装，不要每次开机都点它，也不要手动启动目录里的 QQ.exe。

在 AstrBot 后台创建机器人时，平台选择 OneBot v11。反向 WebSocket 主机填 127.0.0.1，端口保持 6199，再设置一个较长的随机 Token。NapCat 的网络配置里建立 WebSocket 客户端，地址填 ws://127.0.0.1:6199/ws，Token 与 AstrBot 完全一致。心跳和重连间隔可以设为 1000 毫秒。

这两个程序启动顺序不必绝对固定。NapCat 连不到 AstrBot 时会重试，AstrBot 没启动时日志里会出现 ECONNREFUSED 127.0.0.1:6199。看到这个错误先检查 AstrBot 实例是否运行，不要急着重填 QQ 配置。

当天色正常时，两边连上的标志也很直接。AstrBot 日志里出现 aiocqhttp(OneBot v11) 适配器已连接，NapCat 侧不再连续报连接失败。

接上 DeepSeek

DeepSeek 开放平台创建 API Key 后，在 AstrBot 的模型提供商里新增 DeepSeek，粘贴 Key 并保存。然后获取模型列表，选择 deepseek-flash，再把默认对话模型和图片转述模型都切过去。

Key 只显示一次。第一次拿到就应该放进本地密码管理器，或者至少放在一个不会被同步到公开仓库的文本文件里。文章、截图、报错日志和 GitHub Issue 都不要出现完整 Key。

模型接通以后可以先不折腾插件，直接在 QQ 里私聊一句。此时回复可能还是默认助手口吻，这是正常的，人格和插件还没导入。

导入大肥鱼配置包

我用的配置包会把人格、分段回复、表情包、语音、QQ 空间、改签名和主动聊天这些设置一次写进 AstrBot。导入工具是命令行问答式脚本，第一次运行时需要输入后台地址、账号、密码、主人的 QQ 号，再选择记忆和语音方案。

第一次导入建议先选“不装记忆”。先把插件和聊天跑通，后面再单独启用 LivingMemory。语音可以先用免费的本地方案，也可以暂时关闭。

配置包会从 AstrBot 插件市场安装 group_chat_plus、LivingMemory、meme_manager、qzone、qqprofile 和 proactive_chat，还会装入几个随配置包提供的小插件。

这里遇到第一个长坑。group_chat_plus 的下载临时文件一直停在 0 字节，导入工具又看不到下载进度，看起来像死机。检查以后确认插件 CDN 的连接中断，本机 CPU 和模型都没有问题。后来换成从官方市场下载好的本地 ZIP，再在后台“从文件安装”，几十秒就完成了。

如果后台安装弹窗也一直转圈，先检查上一轮导入工具是否还占着插件安装锁。旧任务没有释放时，新的本地安装会排队。必要时关闭旧导入窗口，重启 AstrBot 实例，再上传 ZIP。

两套表情包为什么会等很久

配置包默认会下载两套表情包。名字看起来只是几百张小图，实际仓库压缩包一个约 483 MB，另一个约 143 MB。导入工具单连接下载，没有百分比，网络慢的时候就很容易被误认为卡死。

我最后没有继续让它盲等。表情包插件自己有资源广场，那里能看到真实下载进度，也能取消和重试。加载几千张图对普通聊天没有决定作用，先把机器人主体跑通更重要。

如果也想节省时间，可以在导入前把配置清单里的表情包列表暂时留空，让其余设置先完成。以后进入 meme_manager 的资源广场，再逐套安装。不要把两套大仓库 ZIP 直接塞进普通插件上传入口，它们的目录结构和表情包插件自己的导入格式并不完全一样。

ffmpeg 导致语音发不出去

豆包语音已经生成音频，QQ 里却一直没有语音条。日志里给出的原因很明确，系统没有 ffmpeg，音频格式转换失败。

我先检查了 ffmpeg -version，系统确实找不到这个命令。机器上也没有 winget，所以没法照最简单的包管理器步骤安装。

最后的处理办法是用 Python 的 imageio-ffmpeg 包取得静态 ffmpeg 二进制。

python -m pip install imageio-ffmpeg
      python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"

第二条命令会打印真实路径。把 ffmpeg.exe 放到一个稳定目录，再把该目录写进用户 PATH。长期使用更建议安装完整的 ffmpeg 构建，至少保留 ffmpeg.exe 和 ffprobe.exe。

改完 PATH 以后，AstrBot 需要重启一次，新的环境变量才会被进程读到。也可以用 AstrBot 自带的 Python 做一次真实转换测试，确认 pydub 能找到 ffmpeg，而不是只在终端里能运行。

ffmpeg -version

只要这条命令能打印版本，并且后台重启后语音提供者设置正确，音频转换这一段就通了。

最容易被忽略的账号问题

我中途一度以为 QQ 反复掉线全是风控。完整日志里有一段 KickedOffLine，它确实表示登录状态被服务端判为失效，但再往下看，问题比“风控”具体得多。

当时 NapCat 登录的是大号，小号反而成了聊天对面。日志里大号接收来自小号的私聊，方向和预期完全相反。配置目录里也同时出现了两个账号的 OneBot 配置，当晚被更新的那个属于大号。

这个错误会带来几个连锁现象。大号在手机或电脑上正常使用时，会把 NapCat 这边挤掉；扫码时稍不留神就用手机里当前打开的大号扫了；后台白名单和主人号码仍然正确，消息却总像在绕圈。

正确的方向只有一种。NapCat 登录小号，主人的大号给小号发消息，AstrBot 收到小号的消息，再由小号回复。

重新登录时，先在 NapCat WebUI 里退出当前账号，确认手机 QQ 登录的是小号，再扫码或选择小号进行快速登录。登录成功后看日志前缀，应该出现小号的昵称。千万别把大号挂进 NapCat，大号里的群和联系人比小号复杂得多，风险也更高。

控制台中文乱码怎么看

我后来改成直接手动运行 NapCatWinBootMain.exe，没有使用批处理。启动以后控制台里大量中文变成乱码，错误码和英文路径却仍然正常。

这不是登录失败的直接原因。批处理里原本有一行 chcp 65001，直接启动 EXE 时没有执行它，Windows 控制台仍可能用旧代码页显示 UTF-8 日志。

如果坚持不用 .bat，可以在 PowerShell 里先切换代码页，再进入 NapCat 目录启动。

chcp 65001
      Set-Location -LiteralPath 'D:\NapCat\NapCat.52230.Shell'
      .\NapCatWinBootMain.exe

这样控制台会正常显示中文。二维码本身不会因为控制台乱码失效，这时主要看登录账号、二维码是否过期，以及 WebSocket 是否已经建立。

每天怎么手动启动

我没有配置开机自动启动。每天需要手动打开两个程序。

先打开 AstrBot Launcher，在实例列表里点击启动，等状态变成“运行中”。这一步不要看到后台端口号变了就去改 NapCat 的 6199 端口，两个端口负责的事情不同。

再打开一个 PowerShell 窗口，进行下面的操作。

chcp 65001
      Set-Location -LiteralPath 'D:\NapCat\NapCat.52230.Shell'
      .\NapCatWinBootMain.exe

NapCat 启动后，在浏览器打开 http://127.0.0.1:6099/webui。如果要求输入 WebUI Token，就看控制台里 WebUi Token 那一行。登录 QQ 时选小号。快速登录状态失效就重新扫码，二维码过期以后不要拿旧图反复试，直接刷新。

判断是否真的可用，看两处就够了。NapCat 里有 网络已连接，AstrBot 里有 OneBot v11 适配器已连接。两边都在，再回 QQ 里聊天。

我最后保留的安全习惯

机器人只使用小号，主人账号不交给 NapCat 登录。

后台开启白名单，只允许自己的会话进入。管理员列表填入大号，但不要把管理员权限公开给群里其他人。

电脑上只保留一份 NapCat 进程，不重复点击启动。发现掉线先看进程和端口，不要连续开新窗口。

所有 Key、Token、后台密码、WebUI 地址和二维码都不截图发群。日志可以记录错误码和连接状态，带二维码、账号标识、群号和聊天正文的部分需要打码。

如果 QQ 要求安全验证，就按腾讯页面完成手机号绑定和登录设备清理。验证完成以后仍然反复掉线，换一个更稳定的小号往往比继续改参数更有效。
