在 Windows 上用 Docker 跑 Linux 版 MySQL 的完整过程

📅 2026-10-10  |  Docker MySQL 环境搭建

不想装虚拟机？用 WSL2 + Docker Desktop 在 Windows 里跑一个 Linux 版 MySQL 8.0.26，程序和所有数据都放 D 盘，开机自动启动。

学 MySQL 的时候，课程一路讲到最后，索引那部分突然换到了 Linux 环境演示。老师建议装虚拟机或者买台云服务器，我电脑上本来就有 Windows 版 MySQL，不想为了几节课再背一个虚拟机，就试着用 Docker 在 Windows 里跑一个 Linux 版 MySQL。

中间踩了几个坑，写下来给同样卡住的人。做完之后的效果是这样的，开机后 Docker 和 MySQL 自动启动，打开 DataGrip 连 localhost:3307 就能用，程序和所有数据都放在 D 盘，平时完全不用管。

需要准备什么

Windows 11 就行，家庭版也没问题，我用的就是家庭版。内存 8GB 能跑，16GB 会宽松一些。D 盘留出 10GB 左右，后面镜像和数据都放这里。另外下载 WSL 组件和 Docker 安装包需要网络通畅，这一步耐心一点。

第一步，装 WSL2

Docker 在 Windows 上跑 Linux 容器，底层靠的是 WSL2，可以把它理解成 Windows 里内置的一个轻量 Linux，所以先装它。

以管理员身份打开 PowerShell，运行这一条。

wsl --install --no-distribution --web-download

这里是我遇到的第一个坑。我最初跑的是 wsl --install --no-distribution，命令执行后半天没有任何输出，不报错也不出进度条，看着像卡死。查了资料才知道它默认从微软商店下载组件，国内网络下经常卡住不动。加上 --web-download 之后进度条马上出来了，几分钟装完。

装完用下面这条确认。

wsl --version

能看到版本号（我装出来是 3.0.1）就说明这步过了。

第二步，下载 Docker Desktop 安装包

直接下到我们最终要用的目录里。

mkdir D:\Docker -Force
      curl.exe -L -o "D:\Docker\DockerDesktopInstaller.exe" "https://desktop.docker.com/win/main/amd64/Docker%20Desktop%20Installer.exe"

安装包六百多兆，网络不好时多等一会儿。

第三步，把 Docker 装到 D 盘

这是我踩的最大的坑。我第一次直接双击安装包一路点下一步，装完才发现它默认装到了 C 盘的 AppData 目录里。我的习惯是开发工具都放 D 盘，就想着把文件夹挪过去，结果发现 Docker Desktop 不能直接剪切搬家，它涉及注册表、后台服务和 WSL 集成，复制过去会坏。

正确做法是卸载掉装错的那份，用命令行参数重新安装。

& "C:\Users\你的用户名\AppData\Local\Programs\DockerDesktop\Docker Desktop Installer.exe" uninstall --quiet

然后用参数重装。

Start-Process "D:\Docker\DockerDesktopInstaller.exe" -Wait -ArgumentList `
        'install','--user','--accept-license','--backend=wsl-2',`
        '--installation-dir=D:\Docker\DockerDesktop',`
        '--wsl-default-data-root=D:\Docker\data'

几个参数的含义说一下。--installation-dir 决定程序装在哪，--wsl-default-data-root 决定 Docker 的镜像和容器数据放哪，后者才是占空间的大头。--user 表示按当前用户安装，以后更新不用每次找管理员权限。装完可以去 D:\Docker 看一眼，程序在 DockerDesktop 文件夹，数据在 data 文件夹。

第四步，配置镜像加速

启动 Docker Desktop，接受协议，跳过登录，等右下角任务栏的小鲸鱼变成绿色，说明引擎起来了。然后试着拉镜像。

docker pull mysql:8.0.26

这里大概率会失败，提示连不上 registry-1.docker.io。Docker Hub 在国内直连经常超时，解决办法是配置镜像加速。打开 C:\Users\你的用户名\.docker\daemon.json，没有这个文件就新建一个，写入下面内容。

{
        "registry-mirrors": [
          "https://docker.m.daocloud.io",
          "https://docker.1ms.run",
          "https://docker.xuanyuan.me"
        ]
      }

改完在任务栏的鲸鱼图标上右键重启 Docker Desktop。重新拉镜像，这次很快就下完了。

第五步，启动 MySQL 容器

docker run -d --name mysql8 -p 3307:3306 -e MYSQL_ROOT_PASSWORD=1234 -v D:\Docker\mysql\data:/var/lib/mysql --restart unless-stopped mysql:8.0.26

这条命令里的参数都挺有用，挨个说。-p 3307:3306 把容器里的 3306 端口映射到本机的 3307，用 3307 是因为我电脑上本来就有一个 Windows 版 MySQL 占着 3306，两个错开互不影响。-v 那段把数据库文件挂载到 D 盘，以后就算删掉容器，数据也还在。--restart unless-stopped 让容器跟着 Docker 开机自启。镜像版本特意选了 8.0.26，和课程保持一致。

等半分钟左右初始化，然后检查。

docker ps
      docker exec mysql8 mysql -uroot -p1234 -e "SELECT VERSION();"

第一条能看到 mysql8 的状态是 Up，第二条能打印出 8.0.26，就成功了。

第六步，用 DataGrip 连接

新建 MySQL 数据源，按下面填。

项 值
主机 localhost
端口 3307
用户 root
密码 1234

测试连接，看到绿色对勾就能开始用了。

让它在开机时自动启动

Docker Desktop 设置里虽然有开机启动的开关，但有时候配置不生效，稳妥的办法是直接改配置文件。打开 C:\Users\你的用户名\AppData\Roaming\Docker\settings-store.json，找到 AutoStart 这一项，改成 true。

{
        "AutoStart": true
      }

这样开机后 Docker 自动启动，MySQL 容器也跟着起来（靠前面配好的 --restart unless-stopped）。以后每天的流程就是开机，等一两分钟，打开 DataGrip 直接用。

最后，文件都在哪

D:\Docker\DockerDesktop    Docker 程序
      D:\Docker\data             Docker 引擎数据
      D:\Docker\mysql\data       MySQL 数据

原来的 Windows 版 MySQL 我没动，还在 3306 端口上，两个数据库互不影响，课程实验统一用新的 3307 这个。几个常用的容器命令也放这里备查。

docker stop mysql8     # 停止 MySQL
      docker start mysql8    # 启动 MySQL
      docker logs mysql8     # 查看日志

到这里环境就配好了。整个方案适合不想装虚拟机的人，如果你也在跟这门课，学到 Linux 部分的时候可以参考。
