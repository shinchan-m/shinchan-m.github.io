# AstrBot + NapCat + DeepSeek 通用 QQ 机器人接入教程

## 摘要

这篇教程面向第一次在 Windows 上搭建 QQ 机器人的读者。完成后，电脑上会运行一套本地机器人服务。你的主 QQ 号可以私聊机器人小号，也可以把它拉进群，让它调用 DeepSeek 生成回复。

教程不依赖某个固定人格或配置包。基础聊天、人格、群聊、表情、长期记忆和语音分别讲清楚，你可以只做基础部分，也可以按需要继续加功能。

开始前要先接受一个边界。NapCat 通过非腾讯官方客户端登录 QQ，腾讯可能踢下线、要求安全验证，也可能限制账号功能。QQ 用户协议对第三方登录和自动化消息有约束。准备尝试时使用小号，不要拿常用号做实验。

<h2 id="sec-01">01 完成后会得到什么</h2>

最基础的版本包括四个结果。

1. AstrBot 在本机运行，能打开管理后台。
2. NapCat 登录 QQ 小号，成功连接 AstrBot。
3. DeepSeek 成为默认聊天模型。
4. 主号私聊小号时能收到正常回复。

可选功能包括长期记忆、语音、表情包、群聊插话、主动聊天、QQ 空间和资料修改。它们不是基础接入的前置条件。第一次搭建先完成这四项，后面每加一个插件就单独测试一次。

<h2 id="sec-02">02 适用环境和准备工作</h2>

Windows 10 和 Windows 11 都可以。基础聊天用 8 GB 内存能跑，16 GB 会更宽松。长期记忆如果选本机 Ollama，还要预留几 GB 磁盘和额外内存。

需要一个 QQ 小号。小号最好已经绑定手机号，并能正常登录手机 QQ。新注册的号风控概率更高，遇到验证时也更麻烦。

需要一个 DeepSeek 开放平台账号。注册后在平台里创建 API Key，并先充少量余额。Key 只在创建时显示一次，复制后放进密码管理器，不要写进公开仓库。

安装目录尽量使用纯英文路径，例如下面这样。

```text
D:\AstrBot
D:\NapCat
```

路径里有空格通常也能运行，但后面的命令需要加引号。第一次搭建时，英文路径、无空格目录能少掉一类问题。

如果电脑会自动睡眠，需要关闭睡眠和休眠。机器人依赖本机在线，电脑合盖休眠以后，AstrBot、NapCat 和 QQ 都会停止工作。

<h2 id="sec-03">03 方案选择</h2>

先把需求缩小，不要一开始把所有插件都装上。

| 目标 | 必需组件 | 额外要求 |
| --- | --- | --- |
| 只在私聊里聊天 | AstrBot、NapCat、DeepSeek | 无 |
| 增加长期记忆 | LivingMemory 或同类插件 | Ollama 或云端嵌入接口 |
| 增加语音 | TTS 提供商、语音插件 | ffmpeg，云端语音还要 API 凭证 |
| 增加表情包 | meme_manager 或同类插件 | 额外磁盘空间 |
| 进群聊天 | OneBot 机器人、群聊插件 | 群会话加入白名单 |

这里的“插件”可以由 AstrBot 插件市场安装。不同版本的插件配置项可能变化，安装前要先确认它支持的 AstrBot 版本。

<h2 id="sec-04">04 成本、内存和磁盘怎么估</h2>

DeepSeek 按 token 计费，输入和输出分别计算。私聊里每次发送的上下文越长，费用越高。群聊通常还要经过“是否回复”的判断，模型调用次数会比私聊多。

第一次测试只充少量余额就够。平台价格会调整，文章里不写死具体价格，创建 Key 之前先看 DeepSeek 控制台的当前价格页。

长期记忆也需要模型调用。记忆插件定期把聊天内容总结成短文，总结请求同样会消耗 DeepSeek 额度。嵌入模型负责把文本转成向量，本机 Ollama 不需要按次付费，云端嵌入接口的价格和免费额度要看服务商页面。

语音费用取决于是否使用云端服务。Edge 一类免费方案成本低，声音也更机械。豆包一类云端语音通常按生成时长收费，一段回复合成一条语音，等待时间会比文字回复长很多。

磁盘占用可以按下面几个区间预估。

| 项目 | 大致占用 |
| --- | --- |
| AstrBot 和实例依赖 | 2 GB 左右，随版本增长 |
| NapCat 和 QQ 内核 | 1.5 GB 到 2 GB |
| Ollama 程序和基础模型 | 2 GB 到 4 GB |
| 大表情包资源 | 数百 MB 到数 GB |
| 聊天数据和日志 | 初期很小，长期运行会增长 |

安装前至少留出 10 GB 空间。长期记忆和大表情包全部安装时，留出 15 GB 更稳妥。

<h2 id="sec-05">05 组件分工和端口</h2>

理解消息从哪里经过，排错会快很多。

```text
主号 QQ
  ↓ 发送消息
机器人小号 QQ
  ↓
NapCat
  ↓ OneBot v11 WebSocket
AstrBot
  ↓ API 请求
DeepSeek
  ↓ 返回文本
AstrBot
  ↓
NapCat
  ↓
机器人小号 QQ
```

三个端口分别负责不同任务。

| 端口 | 用途 |
| --- | --- |
| AstrBot WebUI 随机端口 | 打开管理后台 |
| `6199` | AstrBot 接收 NapCat 消息 |
| `6099` | 打开 NapCat 自己的 WebUI |

WebUI 的随机端口每次部署可能变化，`6199` 和 `6099` 通常固定。看到后台端口变化时，不要去改 OneBot 的 `6199`。

<h2 id="sec-06">06 一次完整搭建的顺序</h2>

新手容易把插件、语音和记忆一起装，出错以后不知道是哪一层停了。下面这个顺序能让每一步都有明确的成功标志。

1. 安装 AstrBot 并进入 WebUI。
2. 安装 NapCat，成功登录 QQ 小号。
3. 在 AstrBot 创建 OneBot v11 机器人。
4. 在 NapCat 创建 WebSocket 客户端，确认 `6199` 已连接。
5. 配置 DeepSeek，主号私聊小号能收到回复。
6. 设置白名单、管理员和电脑能力限制。
7. 创建人格和分段回复。
8. 按需要安装群聊、表情、记忆和语音插件。

每一步测试通过再继续。基础聊天没有跑通时，不要先排查豆包语音或本地记忆。

<h2 id="sec-07">07 安装 AstrBot Launcher</h2>

浏览器打开 AstrBot Launcher 的 GitHub Releases 页面，下载 Windows x64 安装包。文件名里通常会带有版本号，以页面最新稳定版为准。

安装时选择前面准备好的英文目录，例如 `D:\AstrBot`。Windows 可能弹出 SmartScreen 提示，确认安装包来自官方 Release 后再运行。

第一次打开启动器以后，先处理组件管理。

1. 打开“高级”里的中国大陆加速选项。
2. 进入组件管理，等待 Python、uv 和 Node.js 下载完成。
3. 三个组件都显示已下载，再创建实例。
4. 实例版本选择当前稳定版。
5. 端口留空或选择自动分配。

创建实例后，启动器会自动下载 AstrBot 本体、创建虚拟环境并安装依赖。安装依赖是耗时最长的一步。进度停在某个数字几分钟并不罕见，只要日志没有报错就继续等。

实例状态显示“运行中”以后，启动器会弹出后台账号和密码。立即登录后台，把默认密码换成自己的强密码。密码只保存在自己手里，不要放进公开截图。

能打开登录页并进入后台，说明 AstrBot 这一层已经可用。

### 7.1 AstrBot 启动失败时

先看启动器日志，不要直接删除实例。常见原因通常能从日志里看出来。

| 日志现象 | 处理办法 |
| --- | --- |
| 组件下载卡住 | 检查加速选项，重试组件下载 |
| 安装依赖报网络错误 | 换镜像或关闭加速后重试 |
| 虚拟环境损坏 | 在故障排除里清空虚拟环境再启动 |
| 后台密码没记下 | 到启动器日志里找第一次启动生成的密码 |
| WebUI 检查失败 | 确认实例端口没有被其他程序占用 |

不要把整台电脑上的 Python 环境随意删除。启动器自己的 Python、uv 和实例虚拟环境是分开的，手动删除容易让实例无法恢复。

<h2 id="sec-08">08 AstrBot 文件放在哪里</h2>

启动器会把公共组件和实例分开保存。

```text
启动器安装目录
  程序本体和卸载器

用户数据目录
  components/       Python、uv 和 Node.js
  instances/        AstrBot 实例
  versions/         实例版本压缩包
```

默认用户数据目录一般位于当前用户目录下。安装时如果改过数据目录，以启动器“高级”页面显示的路径为准。

实例里的 `core/data` 保存配置、人格、插件和数据库。这个目录比程序源码重要得多，迁移前先备份它。

不要在 AstrBot 运行期间直接覆盖 `data` 目录。先在启动器里停止实例，再复制备份。恢复时也先停止实例，覆盖完成后再启动。

常见需要保存的内容包括下面几项。

```text
data/config/             插件配置
data/plugins/            已安装插件
data/plugin_data/        插件运行数据
data/*.db                机器人数据库
data/cmd_config.json     主要配置
```

API Key 和 Token 可能也保存在配置中。备份文件不要上传到公开仓库，不要发给别人。

<h2 id="sec-09">09 安装 NapCat</h2>

从 NapNeko/NapCatQQ 的 Releases 页面下载 Windows Shell 一键包。解压到 `D:\NapCat`，不要直接放在浏览器的临时下载目录。

运行 `NapCatInstaller.exe`。安装器会下载 QQ 内核和 NapCat 本体，下载过程中可能切换到其他镜像。安装完成后会多出一个类似 `NapCat.52230.Shell` 的目录。

QQ 内核大约几百 MB，NapCat 本体通常小很多。安装器会先尝试腾讯官方下载源，失败时再尝试备用仓库。整个过程受网络影响，卡在下载阶段时先看当前文件名和日志，不要连续启动多个安装器。

如果 GitHub 下载很慢，可以使用 AstrBot 官方文档或 NapCat 文档里列出的加速站。第三方加速站会变化，下载完成后要核对发布页给出的文件大小或哈希。

这个目录里有两类常见文件，作用不同。

```text
NapCatInstaller.exe       只用于安装和重装
NapCat.<数字>.Shell       日常运行目录
  NapCatWinBootMain.exe   启动 NapCat 的主程序
  QQ.exe                 由 NapCat 调用，不要手动开
```

安装器报压缩包损坏时，先删除未完成的 `NapCat.Shell.zip` 和残留的 `NapCat.<数字>.Shell`，再重新下载。不要保留半包反复解压。

安装器提示版本目录无法移动时，经常是上一次安装留下了残留文件夹。关闭 NapCat 和 QQ，删除未完成的 `NapCat.<数字>.Shell`，保留已经下载完整的 QQ 安装包，再重新运行安装器。

安装完成后，先确认 `NapCatWinBootMain.exe` 和目标版本目录都存在，再开始登录。缺少主程序或 `versions` 目录，说明安装没有真正结束。

<h2 id="sec-10">10 启动 NapCat</h2>

目录里有批处理时，双击启动批处理最简单。批处理通常会设置 UTF-8 代码页，然后调用主程序。

不用批处理也可以手动启动。打开 PowerShell，先切换控制台编码，再进入实际目录。

```powershell
chcp 65001
Set-Location -LiteralPath 'D:\NapCat\NapCat.52230.Shell'
.\NapCatWinBootMain.exe
```

目录名里的数字按自己的版本填写。PowerShell 不识别 CMD 的 `cd /d`，直接写 `Set-Location` 或 `cd`。

只启动 `NapCatWinBootMain.exe` 这一份。不要同时双击 `QQ.exe`。NapCat 会自己创建 QQ 子进程，手动再开 QQ 会导致重复登录和端口冲突。

启动后控制台会显示 NapCat WebUI 地址和 Token。浏览器打开类似下面的地址。

```text
http://127.0.0.1:6099/webui
```

页面要求登录密钥时，复制控制台里的 `WebUi Token`。这个 Token 不是 QQ 密码，也不是 AstrBot 后台密码。

### 10.1 NapCat 控制台中文乱码

乱码通常来自 Windows 控制台代码页，不会改变 QQ 登录结果。错误码、端口号和网址都是 ASCII，仍然可以正常判断。

把代码页设为 `65001` 后重新启动，中文一般就能正常显示。

```powershell
chcp 65001
```

如果系统终端仍然显示异常，可以换用 Windows Terminal，或在启动批处理里保留编码设置。不要因为乱码反复重装 NapCat。

<h2 id="sec-11">11 Windows 权限和杀毒软件</h2>

日常运行 AstrBot 和 NapCat 通常不需要管理员权限。安装器请求管理员权限时确认来源，之后不要为了省事让所有程序永久以管理员身份运行。

第一次启动可能弹出 Windows SmartScreen 或防火墙提示。SmartScreen 只对可信安装包放行。Firewall 询问是否允许程序访问网络时，只在本机使用就保留私网范围，不要开放公网。

杀毒软件可能扫描刚解压的 QQ 内核和 Node 模块，导致安装器短暂显示“拒绝访问”。先等扫描结束再重试。反复失败时，可以只为明确的安装目录添加排除项，不要关闭整台电脑的实时保护。

<h2 id="sec-12">12 登录 QQ 小号</h2>

NapCat WebUI 提供扫码登录和快速登录。快速登录依赖之前的登录状态，状态失效时会提示重新登录。扫码登录需要使用手机 QQ。

扫码前先确认手机登录的是机器人小号。扫码以后，在手机上点允许登录或确认登录。二维码通常两分钟内有效，过期会生成新的二维码。

登录成功后，控制台会出现账号在线、网络已连接一类信息。快速登录列表里可能同时保存主号和小号，选择时不要点错。

如果列表里有多个账号，先核对昵称和用途。机器人应该使用小号，主号只在手机或普通 QQ 客户端里使用。登录完成后再看 NapCat 日志里的账号昵称，确认不是把主号挂了上去。

手机 QQ 的账号安全设置能减少一些登录失效。检查手机号是否绑定，清理不认识的登录设备，完成腾讯弹出的安全验证。快速登录状态过期时按页面要求重新验证，不保存来源不明的登录凭据。

### 12.1 登录状态失效

日志出现 `KickedOffLine` 时，QQ 账号的当前登录被服务端取消了。常见原因有几类。

- 同一个 QQ 小号又在另一台电脑或另一个机器人程序里登录
- QQ 安全策略要求重新验证
- 手机端主动退出了当前设备
- 二维码或快速登录状态过期

先确认只有一份 NapCat 实例，再检查手机端是否把电脑踢下线。不要连续生成十几张二维码。必要时关闭 NapCat，清理残留 QQ 进程，重新启动一份再登录。

<h2 id="sec-13">13 创建 OneBot v11 机器人</h2>

登录 AstrBot 后台，进入“机器人”，新建机器人。消息平台类别选择 OneBot v11。

填写下面几项后保存。

```text
机器人名称        可以自定义，例如 MyBot
反向 WS 主机       127.0.0.1
反向 WS 端口       6199
Token             自己生成的一串随机字母和数字
```

机器人名称会影响会话 ID。后面设置白名单时，ID 开头的名称要和这里一致。

<h2 id="sec-14">14 配置 NapCat 的 WebSocket 客户端</h2>

打开 NapCat WebUI，进入网络配置，新建 WebSocket 客户端。方向一定要选客户端，让 NapCat 主动连接 AstrBot。

```text
URL       ws://127.0.0.1:6199/ws
Token     与 AstrBot 中的 Token 完全一致
心跳      1000
重连      1000
```

保存并启用配置。AstrBot 日志里应该出现下面这类信息。

```text
aiocqhttp(OneBot v11) 适配器已连接
```

用系统命令也能看到 `6199` 的监听和连接状态。

```powershell
Get-NetTCPConnection -LocalPort 6199
```

只有 `Listen` 表示 AstrBot 已经准备接收连接，但 NapCat 还没连上。出现 `Established` 才说明双方建立了连接。

### 14.1 连接失败的三个检查点

第一，确认 AstrBot 实例正在运行。`ECONNREFUSED 127.0.0.1:6199` 表示这个端口没有服务在监听。

第二，检查 URL 是否完整。`ws://127.0.0.1:6199/ws` 末尾的 `/ws` 不能漏。

第三，对比两边 Token。多一个空格、大小写不同或者引用了旧值，连接都会被拒绝。

<h2 id="sec-15">15 接入 DeepSeek</h2>

打开 DeepSeek 开放平台，充值少量余额，创建 API Key。Key 不要贴在文章中，也不要上传到公开仓库。

注册平台账号后，先完成充值或查看当前赠送额度。进入 API Key 页面，创建一把给 AstrBot 专用的钥匙，名称可以写机器人的用途。复制后先验证有没有多余空格，再粘贴到 AstrBot。

不要购买所谓“无限额度”的共享 Key。第三方中转站可能记录聊天内容和密钥，价格也不透明。使用官方平台时，至少可以从用量页面看到每次调用的消耗。

进入 AstrBot 的“模型提供商”，新增 DeepSeek，把 Key 填进提供商源。保存后点击获取模型列表。

可用模型会随平台更新。基础聊天优先选择速度合适、价格透明的模型。把模型添加进 AstrBot 以后，还要进入配置文件里的模型设置，把默认对话模型指向刚添加的提供商。

主号私聊小号发一句简单问题。能收到模型回复，说明基础流程已经完成。

如果 QQ 能收到消息但没有回复，检查下面几项。

1. 模型提供商 Key 是否保存成功。
2. 默认对话模型是否真的切换到了 DeepSeek。
3. DeepSeek 账户是否有余额。
4. AstrBot 日志里有没有模型鉴权错误。
5. 白名单是否把主号排除在外。

模型费用按输入和输出 token 计算，群聊会多一次或多次判断请求。具体价格以 DeepSeek 官方页面为准，不要照抄旧文章里的价格。

可以在 DeepSeek 控制台设置自己的充值上限。第一次接入不需要一次充很多钱，确认模型可用后再按使用量补充。

<h2 id="sec-16">16 先做安全设置</h2>

机器人能回复以后，马上设置访问控制。否则陌生人或群友可能消耗你的余额，也可能触发管理指令。

用主号私聊机器人，发送下面的命令。

```text
/sid
```

机器人会返回会话 ID。私聊 ID 通常由机器人名称、消息类型和主号 QQ 组成。复制完整 ID，不要只复制 QQ 号。

进入后台的访问控制页面，开启白名单，把会话 ID 加进去。再把主号 QQ 加入管理员列表。

如果机器人要进群，先用小群测试。把群会话 ID 加入白名单，格式以后台实际显示为准。群聊消息多，成本高，开始时把回复概率调低。

最后检查“使用电脑能力”。普通聊天选择“不允许任何环境”。允许执行命令或读写文件后，模型输出的风险会从聊天内容扩大到整台电脑。

<h2 id="sec-17">17 创建人格</h2>

人格可以直接在 AstrBot 后台创建，不需要导入某个固定配置包。

新建人格时至少写清四个方面。

```text
身份        它叫什么，是朋友、助手还是某个角色
语气        简短还是详细，正式还是口语
边界        不知道时怎么回答，哪些事情不能做
关系        谁可以管理它，陌生人消息如何处理
```

人格文本会随请求发送给模型提供商。不要把密码、Key、住址和身份证号写进人格。

保存人格后，在配置文件里把它设为默认人格。修改以后如果在 QQ 里没有变化，发送 `/reset` 清理当前会话，再重新测试。

### 17.1 分段回复

AstrBot 可以把一条长回复拆成多条短消息。进入平台设置里的分段回复，设置拆句规则和随机间隔。

第一次使用可以试 1.5 到 3.5 秒。间隔太长会让聊天变慢，太短则像连续刷屏。群聊和私聊的建议值不同，最好分别测试。

<h2 id="sec-18">18 安装插件</h2>

插件可以从 AstrBot 插件市场安装，也可以从 GitHub 仓库安装。插件市场通常会记录兼容版本和下载地址。GitHub 安装更适合开发者，需要自己确认仓库可信度和版本要求。

装插件前先看三个信息。

1. 插件是否支持当前 AstrBot 大版本。
2. 插件是否要求额外的 Python 包或外部程序。
3. 插件是否会读取消息、图片、联系人或其他敏感数据。

插件安装完成后，如果后台一直转圈，先查看是否有旧安装任务占用锁。重启实例后再试一次通常比连续重复点击更有效。

### 18.1 插件市场、GitHub 和配置包

插件市场适合普通用户。市场记录通常包含下载地址、兼容版本和作者信息。GitHub 适合需要最新版本或自己修改代码的人，安装前要确认仓库地址和版本。

GitHub 连接慢时，可以在 AstrBot 后台的网络设置里测试 GitHub 加速地址。这个设置只影响当前浏览器里的仓库安装，不会改变插件市场已经托管的下载地址。

配置包是可选方案。它通常包含人格、插件参数和导入脚本，适合想快速得到一套完整行为的人。使用前要检查来源、许可证和脚本内容，不要把来路不明的配置包直接运行在存有重要文件的电脑上。

配置包导入失败时，先看它在哪一步停止。插件下载失败可以手动安装后重跑，语音或记忆失败可以暂时选 0 跳过。重跑前看清提示，某些导入工具会把后台手工改过的设置重新覆盖。

### 18.2 群聊插件

群聊插件通常负责判断是否回复、回复概率、打字延迟和频率限制。配置时先从小群、小概率开始。

机器人被 @ 时是否一定回复、普通聊天是否插话、连续回复后是否进入冷却，这些选项需要分别设置。群里人多时，每条消息都调用模型会产生明显费用。

测试时先建一个两三个人的私密小群。把群会话 ID 加入白名单，再用主号 @ 机器人。确认基础回复正常，再打开“普通消息也可能回复”的选项。

群聊插件不能代替白名单。即使插件概率很低，机器人仍会读取群消息，配置白名单和权限时不要省掉这一步。

### 18.3 表情包插件

表情包插件一般有自己的资源广场。资源包下载会显示进度，有的包体积很大，先确认磁盘空间。

安装一套测试就够。一次下载多套大资源时，网络一断就会出现长时间等待。失败以后从插件页面重试，或者换一个镜像地址。

### 18.4 QQ 空间和资料插件

发说说、改签名、改头像这些功能通常需要管理员权限。开启前先确认指令只允许主人使用，公开群里不要让陌生人触发。

自动发说说和自动改资料容易产生意外内容。第一次使用时关闭自动任务，只测试手动命令。

<h2 id="sec-19">19 长期记忆</h2>

普通模型对话只接收有限长度的上下文。聊天轮数很多以后，早期内容会从当前窗口里消失。`/reset` 也会清空当前会话。

长期记忆插件会定期总结聊天内容，再把总结转成向量保存。之后聊到相关话题时，它会检索以前的记忆，把少量内容加入模型上下文。

### 19.1 方案一，本机 Ollama

安装 Ollama 后，使用命令行下载嵌入模型。

```powershell
ollama pull bge-m3
ollama list
```

`ollama list` 能看到 `bge-m3`，说明模型已经下载。常见嵌入接口地址如下。

```text
http://127.0.0.1:11434/v1
```

在 LivingMemory 或同类插件里填写这个地址、模型名称和 1024 维嵌入。Ollama 服务没有运行时，记忆插件会报连接错误。

本地方案的数据和模型都在电脑上，代价是下载体积、内存占用和维护成本。

### 19.2 方案二，云端嵌入接口

硅基流动一类平台也提供 `BAAI/bge-m3`。注册后创建 API Key，把接口地址、Key、模型名称和维度填入插件。

```text
接口地址  https://api.siliconflow.cn/v1
模型      BAAI/bge-m3
维度      1024
```

云端方案不需要本地下载模型，但要检查额度、价格和隐私说明。聊天内容可能被发送到嵌入服务商。

### 19.3 测试记忆是否生效

先聊十轮以上，顺便告诉机器人几件固定的小事，例如喜欢的食物和睡眠时间。然后发送 `/reset` 清空当前会话，再问它刚才提过的内容。

能回答说明记忆已经参与检索。回答不出来时，检查记忆插件是否启用、嵌入提供者是否连通、总结触发轮次是否已经达到。

记忆作用域一旦改变，旧记忆不一定自动迁移。长期使用前先确定是私聊记忆、群聊记忆还是统一作用域。

<h2 id="sec-20">20 语音</h2>

语音属于可选功能。先决定是否接受费用和等待时间，再安装对应插件。

| 方案 | 特点 | 额外要求 |
| --- | --- | --- |
| Edge TTS | 免费，部署简单，声音偏机器 | 可能需要 Python 包和 ffmpeg |
| 豆包语音 | 声音自然，一段回复合成一条 | 火山引擎实名账号和应用凭证 |
| Breeze 本机语音 | 免费，可自定义声音 | 显卡、模型和本机服务 |

Edge TTS 适合先验证语音流程。安装对应语音插件或提供商，选择中文女声，再把发送概率调低。它不需要云端实名账号，失败时重点查 Python 依赖和 ffmpeg。

豆包语音需要火山引擎账号。注册并完成实名认证后，进入豆包语音旧版控制台，创建应用并开通音频生成模型的试用或按量额度。要复制的是应用管理里的 APP ID 和 Access Token，不要拿火山方舟的 API Key 代替。

旧版和新版控制台的产品入口不同。页面名称变化时先看 URL、产品说明和凭证字段，不要凭字段长度猜 Key 类型。导入以后让机器人试念一句短文本，确认云端返回音频，再恢复正常的回复概率。

Breeze 一类本机语音需要显卡、模型和常驻服务。显存较少时可以使用小模型，速度会慢一些。程序启动后要保证语音服务仍在运行，关闭服务以后机器人只能发文字。

大多数语音方案会在最后一步调用 ffmpeg 转码。先在 PowerShell 里检查。

```powershell
ffmpeg -version
```

命令不存在时，安装完整 ffmpeg 构建，把 `bin` 目录加入用户环境变量 `Path`。修改后必须重启 AstrBot，新的进程才会读到新的 PATH。

机器上没有 winget 时，可以使用带静态二进制的 Python 包过渡。

```powershell
python -m pip install imageio-ffmpeg
python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"
```

把打印出的 `ffmpeg.exe` 放进一个固定目录，再把目录写进 PATH。完整构建通常还会提供 `ffprobe.exe`，长期使用更合适。

语音插件配置完成后，明确让机器人发一条语音测试。能收到音频，再调整发送概率。语音生成失败时先看 TTS 鉴权，再看 ffmpeg，最后再看 QQ 发送能力。

<h2 id="sec-21">21 每天启动和关闭</h2>

正常运行时只需要两个主要程序。

| 程序 | 作用 |
| --- | --- |
| AstrBot | 后台、插件、人格和模型 |
| NapCat | 登录 QQ 并转发消息 |

比较稳妥的顺序是先启动 AstrBot，再启动 NapCat。NapCat 启动后会主动连接 `6199`，AstrBot 先运行可以少出现几次连接拒绝。

每天启动的检查过程如下。

1. 打开 AstrBot Launcher，启动实例。
2. 等实例状态变成运行中。
3. 打开 NapCat 主程序，控制台不要关闭。
4. 在 NapCat WebUI 确认 QQ 小号在线。
5. 查看 AstrBot 日志里的 OneBot 适配器是否已连接。
6. 用主号发一句测试消息。

停止运行时，先在启动器里停止 AstrBot 实例，再关闭 NapCat 控制台。直接强制关机可能让数据库和登录状态没有正常写入。

想设置开机自启动，可以在启动器里打开实例自启动，再用 Windows 任务计划程序启动 NapCat。不要同时保留多个手工启动入口，否则可能出现两份 NapCat。

<h2 id="sec-22">22 日志应该怎么看</h2>

排错时先找第一条错误，不要只看最后一行。一个模型鉴权失败可能让后面的插件初始化连续报错，真正的起因仍在最前面。

日志一般有三处来源。

| 来源 | 适合查看什么 |
| --- | --- |
| AstrBot Launcher 日志 | 实例部署、依赖安装、进程启动 |
| AstrBot 后台“数据与日志” | 模型、插件、平台适配器和消息处理 |
| NapCat 控制台或 WebUI | QQ 登录、二维码、OneBot 网络连接 |

AstrBot 日志里的 `aiocqhttp` 表示 QQ 平台适配器，`provider` 或 `completion` 表示模型，插件名通常出现在方括号里。看到错误先确认模块，再去对应页面检查。

NapCat 日志里的 `WebUi Token`、二维码地址和 WebSocket 状态可以帮助判断 QQ 登录。截图或发日志求助前，记得遮住 Token、QQ 号、群号和聊天正文。

需要确认网络连接时，可以用系统命令查看端口。

```powershell
Get-NetTCPConnection -LocalPort 6199
```

`Listen` 表示 AstrBot 已准备接收连接，`Established` 才表示 NapCat 已经连上。只有前者时，不要怀疑模型，先检查 NapCat。

<h2 id="sec-23">23 常见错误排查</h2>

### 23.1 后台打不开

先确认 AstrBot 实例显示运行中。端口变化以后使用启动器的“打开 WebUI”，不要一直尝试旧端口。

### 23.2 `ECONNREFUSED 127.0.0.1:6199`

这个错误表示 NapCat 找不到 AstrBot 的 `6199` 服务。先确认 AstrBot 已启动，再确认机器人平台配置里的端口是 6199。

### 23.3 二维码过期

重新刷新二维码后立刻扫描。手机 QQ 要登录机器人小号，扫码后还要在手机上确认。旧二维码不要截图长期保存。

### 23.4 扫码后提示登录失败

先看 NapCat 完整日志。登录操作可能被同一账号的其他登录踢下线，也可能触发了腾讯安全验证。清理重复实例，确认账号，等待一段时间后再试。

### 23.5 快速登录状态失效

快速登录依赖此前的登录凭据。凭据过期后改用扫码。若手机号或设备验证发生变化，重新完成手机端安全设置。

### 23.6 控制台乱码

先执行 `chcp 65001`，再启动 NapCat。乱码会影响阅读，不会自动改变 QQ 登录状态。

### 23.7 插件安装长时间没有反应

检查插件 CDN 是否可访问，确认是否有旧安装任务占用插件锁。必要时重启实例，使用官方市场下载的 ZIP 本地安装。

### 23.8 语音文件生成失败

检查 `ffmpeg -version`、TTS 提供商凭证和插件日志。ffmpeg 安装后没有重启 AstrBot，旧进程仍可能找不到新 PATH。

### 23.9 能收到消息但不回复

按顺序检查 QQ 是否在线、`6199` 是否有 Established 连接、DeepSeek Key 是否有效、白名单是否包含当前会话、默认模型是否保存。

### 23.10 私聊正常，群里不回复

检查群会话是否加入白名单、机器人是否被 @、群聊插件是否启用，以及群消息概率是否过低。

### 23.11 机器人过一会儿掉线

检查是否开了两份 NapCat，是否在另一台电脑登录了同一个小号，手机端是否主动退出了电脑设备。新小号还可能触发腾讯安全验证。

<h2 id="sec-24">24 安全和隐私</h2>

使用小号登录第三方客户端。主号里有联系人、群聊和重要资料，不适合做隔离测试。

不要把后台、NapCat WebUI 和 OneBot 端口暴露到公网。默认只绑定 `127.0.0.1`，不要在路由器上做端口转发。

DeepSeek Key、OneBot Token、NapCat WebUI Token、TTS 凭证和后台密码都要单独保管。发布截图前遮挡二维码、Token、账号和设备名。

聊天内容会发送给模型提供商。使用云端记忆时，总结后的文本还会发送给嵌入服务。涉及身份证、住址、账号密码和工作文件的内容不要交给机器人。

插件来源要确认。不要为了一个表情包或管理页面随便运行来源不明的安装脚本。安装前查看仓库、许可证和最近更新时间。

QQ 对第三方登录和自动化消息存在风控。掉线后先看日志和账号状态，连续重试只会增加异常记录。账号被限制时停止自动化操作，按平台要求完成验证。

<h2 id="sec-25">25 备份、迁移和重装</h2>

AstrBot 的后台配置、人格、插件和聊天数据库都在实例数据目录里。换电脑或重装启动器之前，先停止实例，再把实例目录完整复制出来。

只备份 `data/plugins` 不够。插件配置、插件运行数据、人格和数据库分别在 `data` 下不同目录，漏掉以后会出现“插件在但配置没了”的情况。

迁移到新电脑时，先安装相同或兼容的 AstrBot 版本，再恢复实例数据。版本跨得太大时，先在一份副本上测试，不要直接覆盖唯一的数据库。

API Key、OneBot Token 和 TTS 凭证不要写在普通备份说明里。备份包也应该放在加密磁盘或受保护的目录。

NapCat 的账号配置和登录缓存位于它自己的版本目录。迁移 NapCat 时，尽量让新电脑重新登录一次，旧登录状态跨设备复制未必有效，也可能增加 QQ 风控。

准备彻底卸载时，先在启动器里停止实例并卸载 AstrBot。NapCat 目录和 AstrBot 数据目录是否删除要分别确认。卸载程序不等于删除用户数据，反过来，直接删目录也可能留下后台服务和开机项。
